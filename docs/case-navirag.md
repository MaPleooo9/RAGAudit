# 真实案例：审计一个「Hit@1 94.1%」的本地 RAG 系统

> 被测系统：**NaviRAG v1.0.1**（离线《艾尔登法环》攻略问答，Python + ChromaDB + 本地
> sentence-transformers，8428 条三层知识库）
> 评估集：NaviRAG 自己的 **85 条人工标注问法 / 8 个分组**
> 结论：**这个 94.1% 是真的**，两套口径只差 1.2pp，而且那 1.2pp 还是我方口径判错。
> 但它的构成很单一——94.1% 里有 **76.5pp 由「实体名硬匹配」提供**，
> 关掉这条规则只剩 17.6%（单路纯向量 12.9%）。

这份报告的全部数字都可以用文末命令复现，原始逐条结果在
[`examples/elden-ring/out/`](../examples/elden-ring/out/)。

---

## 一、为什么拿它当案例

一个评测工具最没说服力的用法，是评测一个自己捏的玩具检索器。
NaviRAG 是真实上线过的项目（有 exe、有 Release、有公开的评估报告），
它的 94.1% 是**作者自己算的**——正好用来做两件事：

1. **验证工具口径**：RAGAudit 独立算一遍，数字能不能对上原作者的结果
2. **验证工具有用**：对上了之后，它能不能说出原作者没说的事

评估集用的是 NaviRAG 仓库里的 `data/elden_ring/eval_set.json`，
与本仓库 `examples/elden-ring/suite.json` **逐字节一致**
（SHA-256 均为 `1d570845…cd96`，已核对）。
没有改题、没有删题、没有挑好跑的题。

| 项 | 值 |
|---|---|
| 知识库 | 8428 条（L1 wiki / L2 逃课 / L3 常规打法） |
| 向量库 | ChromaDB，余弦距离，`search_ef=1000`（精确搜索，保证可复现） |
| embedding | paraphrase-multilingual-MiniLM-L12-v2（本地） |
| 评估集 | 85 条，8 组 |
| 运行环境 | Windows 11 / CPU / Python 3.13.12 / chromadb 1.5.9 / sentence-transformers 6.2.0 / torch 2.14.1 |
| 耗时 | 冷启动（首次加载 torch 与模型）约 60s；热缓存后 85 条题一次跑完约 **16s** |

## 二、结果一：这个 94.1% 没有被口径撑大

| 口径 | Hit@1 | Hit@3 | Hit@5 | MRR | 层准确率@1 |
|---|---|---|---|---|---|
| `lenient`（标题包含即算命中） | **94.1%** | 96.5% | 96.5% | 0.951 | 97.6% |
| `strict`（页面主实体必须全等） | **92.9%** | 96.5% | 96.5% | 0.945 | 97.6% |

**差值 1.2pp。** 按工具自己的判定阈值（≥3pp 才提示「虚高不可忽视」），
这个分数站得住：它不是靠「标题里沾到名字就算对」凑出来的。

### 而这 1.2pp 是工具的误判，不是系统的虚高

差值只来自**一条题**：

| 提问 | 期望 | 实际命中 |
|---|---|---|
| 玛莲妮亚的追忆能换什么 | l1 / 玛莲妮亚 | l1 /《受黄金树雕琢的"腐败女神"玛莲妮亚的追忆》 |

严格口径拒绝它的理由是「页面主实体 ≠ 期望名」——标题多了「受黄金树雕琢的…的追忆」
这层包装。但用户问的就是「追忆能换什么」，这个物品页**恰恰是正确答案**。

所以：这条严格口径是**假阴性**，真实虚高是 **0**。

> 这一点必须写进报告。工具如果只会说「你的分数虚高」，它就是个杠精；
> 它得能承认自己的口径也有错的时候，结论才可信。

## 三、结果二：64% 的题，问句里就写着答案

不依赖人工分组，从题面自动判定信息泄漏等级：

| 泄漏等级 | 含义 | 条数 | 占比 |
|---|---|---|---|
| 显式指名 | 问句直接写着答案实体名 | 54 | 64% |
| 不含实体 | 整句不含实体名，只能靠语义 | 15 | 18% |
| 俗称 | 用的是登记过的俗称 | 15 | 18% |
| 部分同名 | 含同名子串，易指向错误实体 | 1 | 1% |

按分组的实际表现（`lenient`）：

| 分组 | 条数 | Hit@1 | Hit@5 | 难度占比 |
|---|---|---|---|---|
| 逃课意图 | 23 | 100% | 100% | 0% |
| 常规意图 | 22 | 95% | 100% | 23% |
| 口语俗称 | 9 | 100% | 100% | 100% |
| 否定表达 | 8 | 100% | 100% | 25% |
| 知识问答 | 7 | 86% | 100% | 71% |
| **描述提问** | **6** | **50%** | **50%** | 83% |
| 无脑度意图 | 5 | 100% | 100% | 100% |
| 等级过滤 | 5 | 100% | 100% | 0% |

这张表比 94.1% 有用得多：

- **「逃课」「等级过滤」两组 100% 是必然的**——题面直接写着 boss 名，
  实体硬置顶一命中就结束，测的不是语义检索。
- **「描述提问」50%** 才是真实泛化水平：整句不含实体名
  （「开局那个骑马的长枪骑士怎么逃课」「魔法学院最后那个boss怎么正常打」），
  实体规则完全失效，只能靠向量语义。
- 3 条完全未命中，**全部落在描述提问组**，且失败环节已归因：
  1 条 `target_miss`（层对、目标排错）、2 条 `layer_miss`（路由到 L1 wiki 页）。

## 四、结果三：94.1% 是谁挣的

每个变体只关掉一个部件，其余保持线上配置：

| 变体 | Hit@1 | ΔHit@1 | Hit@5 | MRR | 层准确率 |
|---|---|---|---|---|---|
| full（线上） | 94.1% | — | 96.5% | 0.951 | 97.6% |
| full −alias（关俗称表） | 90.6% | **−3.5** | 92.9% | 0.913 | 96.5% |
| full −enhance（关术语增强） | 94.1% | **±0.0** | 95.3% | 0.947 | 97.6% |
| layered −entity（关实体硬置顶） | 17.6% | **−76.5** | 27.1% | 0.210 | 58.8% |
| pure-vector（不分层不增强） | 12.9% | **−81.2** | 21.2% | 0.153 | 35.3% |

读法：

1. **94.1% 里 76.5pp 由「实体硬置顶」这一条规则提供。**
   关掉它，分层加权体系只能到 17.6%——比纯向量的 12.9% 好一点点而已。
   这与第三节的画像互相印证：64% 的题写着实体名，所以规则一开就赢。
2. **别名表值 3.5pp，且只影响「口语俗称」组**（9 条里 9/9 → 5/9）。
   它不改善语义检索，只是把用户说的俗称映射到库里的规范名——和实体规则同类。
3. **术语增强 ±0：关掉不掉分，MRR 只差 0.004。**
   这是审计最该报的一类结论：一个占了链路位置的模块，
   **在当前评估集上无法证明任何价值**，该考虑删掉而不是「留着再说」。

## 五、结果四：关掉别名表，坏的是哪三条

把「无别名」版本当作一次改动，与线上版本逐条 diff：

```text
85 条 → 85 条，Hit@1 94.1% → 90.6%（-3.5pp）。修好 0 条，弄坏 3 条，净 -3 条。
另有 1 条排名前移、1 条排名后退（仍命中，但位置变了）。
```

| 提问 | 期望 | 之前 | 之后 | 归因 |
|---|---|---|---|---|
| 女武神怎么逃课 | 玛莲妮亚 | rank 1 | 未命中 | 排序：正确结果掉出 Top-K |
| 血王怎么逃课 | 蒙格 | rank 1 | 未命中 | 排序：正确结果掉出 Top-K |
| 米凯拉的锋刃怎么逃课 | 玛莲妮亚 | rank 1 | 未命中 | 层路由：Top1 的层变了 |

同时两条**不改变 Hit@1 但值得看一眼**的：

| 提问 | 变化 | 说明 |
|---|---|---|
| 恶兆王蒙葛特怎么打 | rank 2 → 1 | 不走别名反而更准（别名给了错误候选） |
| 碎星怎么无脑打 | rank 1 → 4 | 仍命中，但已到边缘；下一版可能就掉了 |

只报「修好 0 / 弄坏 3」会把后两条吞掉——排名后退的那条，
是下一次回归最先断的地方。

## 六、交叉验证：和原作者的评估脚本对得上

这是本案例最重要的一节。NaviRAG 仓库里有一份自己写的评估报告
（`docs/eval.md`），六种方案的数字与本工具独立跑出来的结果：

| 方案 | NaviRAG 自评 Hit@1 | RAGAudit 实测 | MRR 自评 / 实测 |
|---|---|---|---|
| A 单路纯向量 | 12.9% | **12.9%** | 0.153 / 0.153 |
| C +分层加权（无实体置顶） | 17.6% | **17.6%** | 0.210 / 0.210 |
| D−alias（关别名） | 90.6% | **90.6%** | — / 0.913 |
| D−enhance（关增强） | 94.1% | **94.1%** | 0.947 / 0.947 |
| D 线上（含实体置顶） | 94.1% | **94.1%** | 0.951 / 0.951 |

**五项全部逐位吻合。** 这说明：

- RAGAudit 的 Hit@1 / MRR 口径与原脚本等价，不是靠改判定规则造出来的差异；
- 差异全部来自工具**额外**提供的东西：双口径、泄漏画像、逐条归因、排名变动。

> 口径等价不等于实现相同：RAGAudit 的 `lenient` 只看中文标题，
> 原脚本还会拼上英文 `title`；在这 85 条上没有产生差别。

## 七、这个案例说明什么

| 结论 | 证据 |
|---|---|
| 94.1% 不是刷出来的 | 两套口径差 1.2pp，且差值来自工具误判 |
| 但它高度依赖人工规则 | 关掉实体置顶 → 17.6%；关掉别名表 → 90.6% |
| 真实泛化能力是 50% 一档 | 「描述提问」组 6 条只中 3 条 |
| 有一个模块白占位置 | 术语增强 ΔHit@1 = 0，MRR 差 0.004 |
| 回归风险集中在人工词典 | 3 条坏例全部来自俗称，2 条是「说对了外号」的题 |

**给这个系统的建议顺序**（按证据强度）：先删术语增强，再补描述型问法的
语义召回，最后才是继续扩别名表——扩表只是把 94.1% 撑在那里，
扩不动「描述提问」那 50%。

## 八、局限（必须一起读）

- 只有 85 条题，**1 条题 = 1.2pp**。任何少于 3 条题的差异都不该当结论。
- 评估集由系统作者本人标注，**期望值本身可能有错**（第二节那条就是例子）。
  RAGAudit 能查重复、查泄漏，查不了「这道题的期望答案写错了」。
- 本工具只看检索层。这个 94.1% 的系统，答案质量、幻觉率、拒答行为一概未测。
- 实体硬置顶的低贡献不代表设计错了——它换来了对俗称/错写/省略的鲁棒性，
  只是**这部分能力当前评估集测不出来**，需要补一组「同实体的多种错写」题。

## 九、复现

```bash
git clone https://github.com/MaPleooo9/RAGAudit.git
cd RAGAudit

# 1. NaviRAG 一侧：需要它自己的依赖与已建好的 .vectorstore
#    pip install chromadb sentence-transformers torch numpy requests
set NAVIRAG_HOME=D:\PROJECT\NaviRAG
set PYTHONPATH=examples\elden-ring

# 2. 跑分（原始逐条结果供 diff 使用）
python -m ragaudit run -s examples/elden-ring/suite.json -r navireg_retriever:search ^
    --name "NaviRAG v1.0.1 线上检索器" -k 5 ^
    --alias %NAVIRAG_HOME%\data\elden_ring\aliases.json ^
    -o examples/elden-ring/out/report.md --json examples/elden-ring/out/run.json

# 3. 消融（5 个变体 × 85 条）
python -m ragaudit ablate -s examples/elden-ring/suite.json ^
    -v examples/elden-ring/variants.py -k 5 -o examples/elden-ring/out/ablation.md

# 4. 回归 diff：把「关别名表」当作一次改动
python -m ragaudit run -s examples/elden-ring/suite.json -r navireg_retriever:search_no_alias ^
    --no-profile --json examples/elden-ring/out/run_no_alias.json
python -m ragaudit diff --base examples/elden-ring/out/run.json ^
    --cur examples/elden-ring/out/run_no_alias.json -o examples/elden-ring/out/diff.md
```

适配器只有 [`examples/elden-ring/navireg_retriever.py`](../examples/elden-ring/navireg_retriever.py)
一个文件，`ragaudit` 包本身仍然零依赖。
