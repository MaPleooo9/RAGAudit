# 演示视频录制方案

> 目标：3 分 30 秒，一个窗口录完，零安装新软件。
> 唯一剩余材料。官网要求「视频需展示作品的核心功能与使用流程」。

---

## 一、录前准备（5 分钟，一次做完）

| # | 动作 | 为什么 |
|---|---|---|
| 1 | **全程只用 VS Code 一个窗口**（左侧文件树 + 下方终端） | 关键。Windows 自带录屏只录**当前窗口**，切窗口会黑屏或断开。所有操作在一个窗口内完成 |
| 2 | 终端字体放大：VS Code 终端按 `Ctrl` + `=` 按 4–5 次 | 1080p 下默认字号在视频里看不清 |
| 3 | 编辑器字号放大：`Ctrl` + `=` 按 2–3 次 | 报告文字同理 |
| 4 | 打开勿扰模式：`Win` + `N` → 勿扰 | 避免微信/邮件弹窗入镜 |
| 5 | **完整试跑一遍不录** | 确认无报错、路径正确，再开录 |

### 提前准备好的三个标签页（同窗口内）

在 VS Code 里先打开这三个文件，录的时候直接点标签切换，不做文件搜索：

- `README.md`
- `examples/toy/out/report.md`
- `examples/elden-ring/out/report.md`

> `examples/toy/out/` 下的报告需要先跑一次生成（见镜头 2），也可以提前跑好再录。
> `examples/elden-ring/out/` 的报告**已经在仓库里**，不用重跑真实案例——
> 真实案例冷启动要 60 秒，录制时等不起，也没必要。

## 二、分镜与口播稿

### 镜头 1｜0:00–0:15　开场

**画面**：`README.md` 顶部
**操作**：无

> 「一个 RAG 系统报出『命中率 94.1%』——这行数字本身，不构成任何证据。
> 它可能是真的，也可能来自判定口径太松、题库里写着答案、或者命中的是手工维护的俗称表。
> RAGAudit 做的事是：审计这个分数能不能信。」

### 镜头 2｜0:15–0:50　零安装跑通

**画面**：终端
**操作**：逐字输入（不要粘贴，观众看得清）

```bash
cd D:\PROJECT\RAGAudit
python examples/toy/run_demo.py
```

**等待**：约 3 秒，滚完即可

> 「不需要 pip install，不需要向量库，不需要 embedding 模型。
> 三秒跑完，生成三份报告：跑分、消融、回归对比。」

**注意**：输出滚完后按 `Ctrl` + `L` 清屏再进入下一镜头，画面干净。

### 镜头 3｜0:50–1:25　双口径：把虚高算出来

**画面**：点开 `examples/toy/out/report.md`，滚动到两个变体的分数行
**操作**：鼠标划过 `lenient Hit@1 90.0%` 和 `strict Hit@1 80.0%` 这两行

> 「同一个检索结果，按两套口径各算一遍。
> 宽松口径 90%，严格口径 80%——差的这 10 个百分点不是误差，
> 是有 10% 的命中共依赖了宽松匹配。报告永远并列呈现，不挑好看的那个报。」

### 镜头 4｜1:25–1:55　消融：这个分是谁挣的

**画面**：点开 `examples/toy/out/ablation.md`

> 「再关掉一个部件跑一遍，差多少就是它的真实贡献。
> 这里关掉别名表，命中率掉 10 个百分点——说明这 10 分是别名表挣的，不是语义检索挣的。
> 反过来，如果关掉之后分数变高，工具会单独把那个模块标出来：负收益的东西不该留着。」

### 镜头 5｜1:55–2:40　真实案例（核心）

**画面**：点开 `examples/elden-ring/out/report.md`，停在分数表与结论段

> 「这是拿一个已经上线的系统做的真实审计：8400 多条知识库，85 条人工评估集，原样未改。
> 它自报命中率 94.1%，我们算出来也是 94.1%——两套口径只差 1.2 个百分点，
> 而且这 1.2 个点还是我们自己严格口径判错的。所以这个数是真的。
>
> 但审计的价值不在确认，在后半句：关掉实体名硬匹配，整条链路只剩 17.6%；
> 单路纯向量只有 12.9%。也就是说，94.1 里有 76.5 个百分点，
> 是因为问句里本来写着答案的名字。
>
> 真正考验语义的那一组——整句不含实体名的描述式提问——命中率只有 50%。」

### 镜头 6｜2:40–3:10　回归：坏在哪一条

**画面**：点开 `examples/toy/out/diff.md`
**操作**：指到「弄坏 1 条」和它下面那行归因

> 「最后一件事：改完之后，是哪几条坏了。
> 不是只掉一个总分，而是逐条对齐——这一条从命中变成未命中，归因是排序掉了。
> 还有一个专门的类别叫『移除』：把难题删掉同样能让平均分上涨，所以删题必须单独报出来。」

### 镜头 7｜3:10–3:30　收尾

**画面**：切回 `README.md` 顶部

> 「RAGAudit，检索评测审计工具。Apache-2.0 开源，零依赖，
> 仓库地址 github.com/MaPleooo9/RAGAudit，clone 下来三秒就能跑。
> 谢谢。」

## 三、怎么录（零安装）

Windows 自带，不用装任何东西：

| 方法 | 快捷键 | 说明 |
|---|---|---|
| **Xbox Game Bar**（推荐） | `Win` + `Alt` + `R` 开始/停止 | 录当前活动窗口，自动存到 `视频/捕获` |
| 截图工具（Win11） | `Win` + `Shift` + `S` → 切到「录制」 | 可框选区域录制 |

**录完立刻检查**：文件在 `C:\Users\你的用户名\Videos\Captures\`，用系统播放器看一遍。

**麦克风**：笔记本内置麦就够，环境安静即可。**口播比字幕重要**——
评审多半不会开字幕，但一定会开声音的前 10 秒。

## 四、上传与取链接

| 项 | 要求 |
|---|---|
| 平台 | B 站（评审在国内，访问稳定），**必须公开可见、无需登录** |
| 标题 | `RAGAudit：RAG 检索评测审计工具 · 3 分钟演示` |
| 分区 | 科技 → 计算机技术 |
| 简介 | 放仓库链接 + 一句话定位 + 标注「赛道一参赛作品」 |
| 时长 | 3–4 分钟，不要超过 5 分钟 |
| 画质 | 1080p 即可（赛道一无分辨率硬性要求，那是 AIGC 赛道的规定） |

上传后**用无痕窗口打开一次**，确认不登录也能看——评审不会登录。

## 六、嫌麻烦的极简版（90 秒）

如果时间紧，砍到两个镜头也符合要求（展示核心功能 + 使用流程）：

1. 终端跑 `python examples/toy/run_demo.py`（15 秒画面）
2. 打开 `examples/elden-ring/out/report.md`，讲真实案例那 4 句话（40 秒）
3. 一句话收尾（10 秒）

**先有，再求好。** 一个 90 秒的清晰录屏，远胜一个没录出来的 3 分钟精品。
