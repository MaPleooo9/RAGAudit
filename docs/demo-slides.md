# 静态截图版演示视频（10 张图 + 配音）

> 适用：不想录屏、不想本人出声。
> 时长：约 **1 分 50 秒**。
> 做法：截 10 张真实运行结果的图 → 软件生成配音 → 按顺序拼起来。

---

## 一、先截图（约 15 分钟）

### 截图前 3 个准备

1. **终端字体放大**：VS Code 终端按 `Ctrl` + `=` 按 5 次（截图会被放大，字小了糊）
2. **窗口拉满**：宽度占满屏幕，高度只留需要的部分
3. **关勿扰**：`Win` + `N` → 勿扰（右上角不能有微信弹窗）

截图工具：`Win` + `Shift` + `S`，截完在截图工具里**用红框圈出关键数字**再保存。

### 10 张清单

| # | 文件名 | 截什么 | 怎么得到 |

### 收尾卡（第 11 张，剪辑软件内制作）

黑底白字，居中两行，停留约 3 秒：

```
RAGAudit · 检索评测审计工具
github.com/MaPleooo9/RAGAudit
```

> 别用截图。文字卡在剪辑软件里能放大到清晰可读，截图反而会糊。

### 跳行号的方法

VS Code 里按 `Ctrl` + `G`，输入行号（如 `9`）回车，光标直接跳到那一行。
再配合 `Ctrl` + `B` 收起左侧边栏，一屏能多显示近 1/3。

**截图时不要截整个窗口**，用 `Win` + `Shift` + `S` 拖框只框住那段内容——
一张图高度控制在 500–700 像素左右最舒服，太高在视频里字会变小。

### 边界自查（踩过一次）

- **不要从表格中间开始截**：行号往上翻一行，如果那是上一张表的尾行（列数往往不同），
  截图会变成一个孤零零的行，观众会以为是新表开头。
- **不要切在表格末尾**：表头有几列、数据有几行，截到底为止，别少最后一行。
- 判据：**表头在哪开始，最后一行在哪结束。**

**命名必须带 `01-` 到 `10-` 前缀**——导入剪辑软件后会自动按文件名排序，
省掉手工排顺序的时间。

> 第 2 张是整片唯一的「真实执行证据」，务必截到路径和输出，不要只截一行命令。

## 二、配音文案（10 段，逐段生成）

在剪映 / 必剪里用「文本朗读」**逐段**生成，不要一次性全贴——
一段对应一张图，方便对齐。

| # | 文案 | 约时长 |
|---|---|---|
| 1 | RAGAudit，一个审计 RAG 评测分数可不可信的工具。 | 6s |
| 2 | 不需要安装任何东西，一条命令跑起来，三秒生成三份报告：跑分、消融、回归对比。 | 12s |
| 3 | 同一份结果，按宽严两套口径各算一遍。宽松九成，严格八成。差的这十个百分点，就是被宽松匹配撑出来的。 | 15s |
| 4 | 再关掉别名表跑一遍，命中率掉十个点。说明这十分是别名表挣的，不是语义检索挣的。 | 12s |
| 5 | 改完之后坏在哪一条？逐条对齐，还给出归因：是层路由错了，还是排序掉了。 | 11s |
| 6 | 这是真实案例：八千四百条知识库，八十五条人工评估集，原样未改。它自报九十四点一，我们算出来也是九十四点一，两套口径只差一点二个百分点。 | 20s |
| 7 | 但分数是谁挣的？关掉实体名硬匹配，整条链路只剩百分之十七点六；单路纯向量只有百分之十二点九。 | 15s |
| 8 | 也就是说，九十四点一里面，有七十六点五个百分点，来自问句里本来就写着答案的名字。 | 13s |
| 9 | 真正考验语义的是描述式提问：整句不含实体名。这一组的命中率，只有百分之五十。 | 13s |
| 10 | 三十四个单测，零依赖，零点零零六秒跑完。 | 9s |
| 11 | Apache-2.0 开源。仓库地址在屏幕上，clone 下来三秒就能跑。谢谢。 | 12s |

**数字读法的坑**：上面已经用中文写数字了（「九十四点一」而不是 `94.1%`），
这是为了避开 TTS 把 `94.1%` 读成「九十四点一百分号」或读成「九十四点一是」。
**试听第一段时确认数字读得对**，不对就把那段的数字改成中文再生成一次。

## 三、合成（约 20 分钟）

1. 剪映 / 必剪 → 新建项目 → 导入 10 张图，**按文件名顺序**拖进主轨道
2. 全选图片，统一时长先设 8 秒
3. 逐段「文本朗读」生成配音，拖到对应图片下方
4. **按音频长度调图片时长**：图片比声音长 0.5 秒即可，长了会冷场
5. **不加背景音乐**（版权风险，且会盖住配音）；不加转场特效
6. 导出 1080p，文件名 `RAGAudit-演示视频.mp4`

### 视觉引导（很重要）

静态图没有光标移动，观众不知道该看哪儿。配音说到数字时，
**用剪映的「贴纸 → 矩形框 / 箭头」把那个数字圈出来**，出现 2 秒消失。
至少给第 3、7、8、9 张各加一个框，这四张是核心结论。

**宽高比极端的截图不要拉满屏**（如第 10 张的单测输出，约 780×110）：
放到画面中间偏下，高度占约四分之一，上下用深色背景铺满。
拉满会变成一条细长条，看着像加载失败。

## 四、这个方案的真实性

| 担心 | 实际情况 |
|---|---|
| 截图会不会被认为「作品没跑起来」？ | 第 2 张是真实终端输出，含完整路径 `D:\PROJECT\RAGAudit\examples\toy\out` 和三份报告文件名，配合公开仓库可核对 |
| 没有现场操作会不会扣分？ | 官网要求「展示核心功能与使用流程」，10 张图已覆盖「装不了 → 跑起来 → 看报告 → 得结论」全流程 |
| 与录屏相比弱在哪 | 弱在「临场感」，强在**没有一次录坏的返工成本**。时间紧的时候这个交换是划算的 |

**如果还剩时间**，补一段 15 秒的真实终端滚动录屏插在第 2 张后面，
现场感立刻回来。这属于加分项，不是必需项。
